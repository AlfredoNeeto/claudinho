## Ranked gaps

1. C14 has not run. It is manual, on the user's work PC, and pending the user. It is the only proof that Claude Code runs a user `Stop` hook under the company's managed settings and expands the `~/...` command (door 1, Assumptions "Comando do hook no Windows" `n`). To close it, run `claudinho.exe install --hook` on the work PC, send one message, then check `%LOCALAPPDATA%\Claudinho\snapshot.json` and the screen.
2. Precision gap in C15. `Assert.Contains("hook", stdout)` (`pc/Claudinho.Tests/HookTests.cs:188`) is already satisfied by the `install [--hook]` text that `:189` asserts. If the `hook` verb were dropped from the usage line, the test would stay green. The check text says only "contém `hook`", so the assertion matches the check, and the check is the imprecise part. Today the verb is there (`pc/Claudinho/Program.cs:49`, `| hook |`).
3. Coverage gap in the checks for AC 7. AC 7 lists "o arquivo não existe **ou não pode ser lido**". The checks' own set "entradas recusadas pelo AC 7 (5)" omits the unreadable-file member, so no proof covers it. By reading, it is handled: an `IOException` or `UnauthorizedAccessException` from the `FileStream` at `pc/Claudinho/Hook.cs:35` is caught at `:20`, so the hook returns 0 before `Snapshot.Write`. It is unproven, not wrong.
4. Low, performance. Every `Stop` re-reads and `JsonNode.Parse`s the whole transcript (`pc/Claudinho/Hook.cs:37-45`), and Claude Code waits for a `Stop` hook to finish. On a long session (transcripts of tens of MB) this adds latency to every reply. The plan's Out of scope rejected `tok` partly because it would need "ler o arquivo inteiro a cada resposta", but the implementation already does that to find the last entry. No AC sets a time bound, so this is not a check failure.
5. Low, churn. `c1dda59` rewrote `.specs/STATE.md` from LF to CRLF. The diff shows all 15 lines changed, and with `--ignore-cr-at-eol` it is 2 insertions and 1 deletion. C16 still passes, because `Select-String` strips the line terminators.
